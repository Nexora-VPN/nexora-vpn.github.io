# Shadowsocks

Shadowsocks به‌جای TLS با یک کلید رمزنگاری می‌کند: بدون گواهی، بدون دامنه، یک
پورت برای TCP و UDP. پنل آن را با یک کلید برای هر کاربر سرو می‌کند، پس هر حساب
جداگانه شمرده، محدود و خاموش می‌شود.

## به چه کاری می‌آید {#what-it-is-good-for}

- **یک پروتکل سبک بدون TLS** برای اپ‌ها و روترهایی که از آن پشتیبانی می‌کنند.
- **ترافیک UDP** مثل تماس‌ها و بازی‌ها، روی همان پورت.
- **همه‌ی خانواده‌های اپ**: لینک‌های اشتراک‌گذاری، اپ‌های Clash (mihomo)، اپ‌های
  sing-box و اپ‌های مبتنی بر Xray همه آن را می‌خوانند.

ترنسپورت و TLS ندارد، پس نمی‌شود آن را پشت CDN برد.

## ساختن آن {#create-it}

**اینباندها ← افزودن**، نوع `shadowsocks`. فرم کلی در [[use/inbounds]] آمده است.
پیش‌فرض‌ها برای ذخیره آماده‌اند: یک روش ۲۰۲۲ و یک کلید سرور ساخته‌شده.

| فیلد (زبانه‌ی **Protocol**) | |
| --- | --- |
| **Method** | الگوریتم رمز. یک روش `2022-blake3-…` را نگه دارید مگر اینکه اپی روش قدیمی‌تری لازم داشته باشد |
| **Server password** (پیشرفته) | کلید خود اینباند که برایتان ساخته می‌شود |
| **Network** (پیشرفته) | `tcp`، `udp`، یا خالی برای هر دو |

## روش‌ها {#methods}

| روش | طول کلید |
| --- | --- |
| `2022-blake3-aes-128-gcm` (پیش‌فرض) | ۱۶ بایت |
| `2022-blake3-aes-256-gcm` | ۳۲ بایت |
| `2022-blake3-chacha20-poly1305` | ۳۲ بایت |
| `aes-128-gcm`، `aes-256-gcm`، `chacha20-ietf-poly1305`، `xchacha20-ietf-poly1305` | هر گذرواژه‌ای |
| `none` | بدون رمزنگاری |

روش‌های ۲۰۲۲ کلیدهایی با طول دقیق لازم دارند که به base64 نوشته می‌شوند.
**Server password** باید با روشش جور باشد: کلید ۱۶ بایتی برای
`2022-blake3-aes-128-gcm` و کلید ۳۲ بایتی برای دو روش دیگر. اگر روش را عوض
می‌کنید، کلیدی با طول درست هم بسازید، وگرنه نود اینباند را نمی‌پذیرد.

روش‌های قدیمی‌تر برای اپ‌هایی هستند که از ۲۰۲۲ پشتیبانی نمی‌کنند. `none` ترافیک
را بی‌رمز می‌فرستد و فقط برای آزمایش است.

## کلید برای هر کاربر {#keys-per-user}

هر حساب دو کلید Shadowsocks روی زبانه‌ی **اطلاعات ورود** خودش دارد:
**کلید Shadowsocks (۱۶ بایت)** و **کلید Shadowsocks (۳۲ بایت)**. پنل کلیدی را
برمی‌دارد که با روش اینباند جور است، و اپ کلید سرور و کلید کاربری خودش را با هم
در لینکش می‌گیرد. در روش‌های قدیمی‌تر، به‌جای این‌ها از **گذرواژه**‌ی کاربر استفاده
می‌شود.

همین است که اینباند را چندکاربره می‌کند: هر کاربر کلید خودش را دارد، پس ترافیک
برای هر حساب شمرده می‌شود و کاربر غیرفعال‌شده فوراً از کار می‌افتد.

::: warning هرگز بدون کاربر سرو نمی‌شود
اینباند Shadowsocks بدون کاربر، سروری تک‌کلیدی می‌شد با همان کلیدی که هر لینک
حمل می‌کند. پنل چنین اینباندی را تا وقتی دست‌کم یک کاربر رویش نباشد از چیزی که
برای نود فرستاده می‌شود کنار می‌گذارد.
:::
