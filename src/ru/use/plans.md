# Тарифы

[[~plan|Тариф]] — заготовка лимитов, с которой создаётся новый пользователь:
объём, срок, ограничения на устройства и скорость, цикл сброса и шаблоны.
Оформляйте тарифами то, что вы продаёте, чтобы все учётные записи одного вида
начинались одинаково.

<NxShot page="plans" alt="Страница тарифов: список тарифов с объёмом, сроком, лимитами и группой" />

## Тариф применяется один раз {#a-plan-is-applied-once}

Когда вы создаёте пользователя из тарифа, панель копирует значения тарифа в
учётную запись, и на этом всё. После этого учётная запись никак не связана с
тарифом.

- Изменение тарифа никогда не меняет уже созданные из него учётные записи.
  Можно менять цены и лимиты в каталоге, не затрагивая то, что клиенты уже
  купили.
- После удаления тарифа его учётные записи сохраняют все выданные им лимиты.
- Последующее изменение учётной записи не применяет тариф заново.

Единственный след, который тариф оставляет в учётной записи, — её **Группа**
(см. ниже): по ней учётные записи тарифа и находятся.

## Создание тарифа {#creating-a-plan}

Нажмите **Добавить** на странице **Тарифы** (в боковом меню под
**Пользователи**).

| Поле | |
| --- | --- |
| **Название** | под каким именем тариф предлагается в форме пользователя |
| **Порядок** | место тарифа в списке. При равных значениях действует порядок создания. |
| **Объём** | квота трафика в ГБ. `0` — без ограничений. |
| **Срок (дней)** | сколько действует учётная запись. `0` — бессрочно. |
| **Начать с первого подключения** | отсчитывать срок с первого подключения клиента, а не с момента создания (см. ниже) |
| **Ограничение скорости**, **Лимит адресов**, **Лимит устройств** | как у пользователя. `0` — без ограничений. См. [[use/users]]. |
| **Автосброс** | сбрасывать израсходованный трафик по циклу: каждые N дней, еженедельно, ежемесячно или ежегодно, по григорианскому или персидскому календарю. См. [[use/users#reset-cycles]]. |
| **Все шаблоны**, **Шаблоны** | на каких шаблонах, а значит и узлах, обслуживаются учётные записи тарифа |
| **Группа** | записывается в каждую учётную запись, созданную тарифом |
| **Префикс имени**, **Суффикс имени** | добавляются вокруг имени, введённого при создании: префикс `r1_` превращает `ali` в `r1_ali` |
| **Описание** | заметка для вас |

## Фиксированная дата или первое подключение {#fixed-date-or-first-connection}

**Начать с первого подключения** определяет, когда начинается срок:

- **Выключено: фиксированная дата.** Дата окончания задаётся при создании
  учётной записи: 30-дневный тариф, созданный сегодня, закончится через 30
  дней, пользовался им клиент или нет. Список показывает только срок.
- **Включено: с первого использования.** Учётная запись ждёт в состоянии
  **Не начат** и не истекает, пока впервые не передаст трафик. Тогда и
  начинается срок. Список помечает такие тарифы **с первого подключения**.

Выбирайте второй вариант для учётных записей, которые продаются заранее,
например пакет, переданный реселлеру или напечатанный на карточках: никто не
теряет дни, пока настраивает приложение.

## Создание пользователей из тарифа {#creating-users-from-a-plan}

В форме пользователя **Тариф** предлагает **Без ограничений**,
**Задать лимиты вручную** и все тарифы. Выбор тарифа заполняет его лимиты и
скрывает их, потому что значения принадлежат тарифу. Форма показывает
итоговое имя с префиксом и суффиксом тарифа (**Будет сохранён как {name}**).

Пакетное создание (**Создать пользователей пакетом…**) тоже принимает тариф,
поэтому весь пакет начинается одинаково. См. [[use/user-operations]].

## Тарифы для реселлеров {#plans-for-resellers}

Тариф — это ещё и способ контролировать, что продаёт
[[~reseller|реселлер]]. В учётной записи реселлера на странице
**Администраторы**:

1. Включите **Продавать только по тарифам**.
2. Выберите **Разрешённые тарифы**.

С этого момента каждая учётная запись, которую создаёт реселлер, должна
создаваться из одного из этих тарифов, и панель применяет лимиты тарифа,
что бы ни было указано в запросе. Позже реселлер может изменить имя и учётные
данные учётной записи, но ни одного лимита. Он видит только те тарифы,
которые ему разрешено продавать. См. [[use/resellers]].

Роль также может ограничить самый длинный тариф, который могут продавать её
учётные записи (**Длина тарифа (дней)**), с отсчётом от первого подключения
клиента. См. [[use/roles]].
