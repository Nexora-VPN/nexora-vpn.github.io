# 邮件

邮件服务通过电子邮件发送面板通知：与 [[telegram|Telegram 服务]]发送的通知相同，发往为面板账户确认过的地址。每个地址只接收其账户有权查看的内容，因此代理商的地址只会收到关于它自己客户的通知。该服务位于 **服务 → 邮件**，由主管理员设置。

## 连接邮件服务器 {#connecting-a-mail-server}

| 设置 | |
| --- | --- |
| **SMTP 服务器** | 邮件服务器的名称，例如 `smtp.example.com`；不含协议，不含端口 |
| **端口** | 留空 = STARTTLS 用 587，TLS 用 465，不加密用 25 |
| **加密** | 连接的保护方式（见下文） |
| **证书** | **验证**，或 **不验证（自签名）** |
| **用户名**、**密码** | 登录凭据；用户名留空则不登录直接发送 |
| **发件人** | 邮件的发件地址，可带名称：`Nexora <panel@example.com>` |

打开 **服务已开启**，保存，然后点击 **测试**。测试使用已保存的设置，因此请先保存。密码保存后不会再显示：留空即保留已保存的密码。

### 加密方式 {#security-modes}

| 方式 | 适用场景 |
| --- | --- |
| **STARTTLS** | 把明文连接升级为加密连接的服务器，通常使用 587 端口 |
| **TLS** | 从第一个字节起就加密的服务器，通常使用 465 端口 |
| **不加密** | 仅限本服务器上或内网中的中继：所有内容（包括登录凭据）都以明文发送 |

只有当你自己的邮件服务器使用自签名证书时，才选择 **不验证（自签名）**。连接仍然是加密的，但路径上的任何人都可能冒充该服务器并读取密码。

大多数服务器只允许从你拥有的地址发信，因此请把 **发件人** 设为你自己的某个地址。

::: tip Gmail 和其他大型邮件服务商
它们会拒绝通过 SMTP 使用你的普通密码，并返回类似 `534 Application-specific password required` 的响应。请为该邮箱开启两步验证，并改用服务商提供的应用专用密码。
:::

## 添加地址 {#adding-an-address}

1. 点击 **添加地址**。保存 SMTP 服务器和发件人之后才可使用。
2. 输入 **地址**，并选择它所属的 **账户**。
3. 选择通知的 **语言**。
4. 选择 **事件**：**该账户可读的全部内容**（包括以后版本新增的事件），或取消勾选后自行选择。账户无权查看的事件显示为灰色。
5. 点击 **发送验证码**。一个六位数验证码会发送到该地址。
6. 输入验证码，然后点击 **确认**。

验证码在十分钟内有效，最多尝试五次；**重新发送** 会发送一个新的验证码。面板从不向未经确认的地址发送任何内容，因此即使地址输错，也不会把你客户的名字发给陌生人。

每个账户都可以在自己菜单的 **我的邮件** 中，按同样的步骤添加自己的地址。代理商无需主管理员协助。

## 收到的内容 {#what-arrives}

每条通知是一封使用该地址所选语言的邮件：发生了什么，然后是对人有用的字段。[[reference/events]] 中的任何事件都可以选择；[[telegram#what-arrives]] 一节列出了运营者通常保留的事件。代理商的地址只会收到关于它自己的用户和它自己账户的事件。

## 地址列表 {#the-address-list}

每一行显示 **地址**、其 **账户**、**事件**、**语言** 和 **添加于**，并有一个用于暂停的开关。在行菜单中：

- **编辑**：修改事件或语言。
- **发送测试邮件**。
- **投递记录**：发送到该地址的每条通知，附有服务器的回复，每条都可以点击 **重新发送**。
- **删除**：该地址不再接收通知；再次添加需要新的验证码。

地址的重试方式与 Webhook 相同（参见 [[webhooks]]），因此在邮件服务器不可用期间发送的通知，会在恢复后送达。服务关闭期间，地址不会收到任何内容。

删除账户会移除它的地址；主管理员在 [[admins]] 页面重置其密码时也会移除。
