# 模板

[[~template|模板]]是一组节点所提供的完整配置。你用池中的部件构建模板，把它交给一个或多个节点，模板上的每个节点提供的内容都与模板完全一致。本页介绍模板包含哪些内容、节点和用户如何使用模板，以及修改模板时会发生什么。

<NxShot page="templates" alt="模板页面：顶部是已分配、未分配和空模板的统计条，下方是模板名称列表，附有入站、出站和端点数量" />

模板位于**核心配置 → 模板**。

## 模板包含什么 {#what-a-template-holds}

各个部件本身放在共享池中，每个池有自己的页面。模板从这些池中挑选部件，并加上只对整个节点有意义的设置。

| 部件 | 来源 | 模板如何使用它 |
| --- | --- | --- |
| [[~inbound\|入站]] | [[inbounds]] | 用户连接的入口 |
| [[~outbound\|出站]] | [[outbounds]] | 路由可选择的出口 |
| [[~endpoint\|端点]] | [[endpoints]] | WireGuard、OpenVPN 等接口 |
| [[~rule-set\|规则集]] | [[rule-sets]] | 路由规则可以匹配的列表 |
| 路由 | 在模板中编写 | 规则和**默认出站** |
| DNS | 在模板中编写 | DNS 服务器和 DNS 规则 |
| 日志与 NTP | 在模板中编写 | 节点的日志级别和时间同步 |

同一个入站、出站或端点可以出现在多个模板中。在池中修改一次，包含它的所有模板以及这些模板上的所有节点都会得到这项修改。

## 创建模板 {#creating-a-template}

1. 打开**核心配置 → 模板**，点击**添加**。
2. 在**常规**中填写**名称**和可选的**备注**。
3. 选择它包含的**入站**、**出站**和**端点**。
4. 在**路由**中选择需要的**规则集**并编写规则，或从预设开始（见[预设](#presets)）。
5. 在 **DNS** 中添加 DNS 服务器，或从预设开始。
6. 点击**保存**。

编辑器有五个标签页：

- **常规**：名称、备注，以及入站、出站和端点选择器。
- **路由**：规则集、规则和默认出站。见 [[routing]]。
- **DNS**：DNS 服务器和 DNS 规则。见 [[routing#dns]]。
- **日志与 NTP**：节点的日志级别和可选的时间服务器。
- **高级（JSON）**：合并到节点配置中的额外顶层配置块，用于表单中没有的设置。

既没有入站也没有端点的模板不为任何用户提供服务。列表会标记它，统计条将它计入**空**。

## 把模板交给节点 {#giving-a-template-to-nodes}

一个节点运行一个模板。设置方法：

1. 打开**节点**并编辑该节点。
2. 在**模板**中选择模板。
3. 保存，然后等待节点显示为已连接。

没有模板的节点不提供任何服务。多个节点可以共用一个模板，这也是运营集群的常见方式：每类服务器一个模板，同类服务器都使用它。

节点还可以在模板之上携带一些自己的内容：额外的出站、额外的端点，以及只在该节点上替代模板路由的路由覆盖。见 [[nodes]] 和 [[routing#node-override]]。

## 哪些用户可以访问模板 {#which-users-reach-a-template}

每个[[~user|用户]]属于一个模板、多个模板或**全部模板**。用户只在其所属模板的节点上开通，**全部模板**会让用户出现在每个节点上。新用户默认可以访问所有模板。在用户表单的**模板**中设置；见 [[users]]。

模板的入站和端点为属于该模板的用户提供服务。你永远不需要手动把用户加到入站中：用户会在包含该入站的每个模板上自动开通。

有些入站类型在没有任何用户时会对任何人开放，或者无法启动：SOCKS、HTTP 和 mixed 代理、Shadowsocks 以及其他一些类型。当它们的模板中还没有用户时，面板不会把它们发送给节点，等到第一个用户加入时再加回来。

## 修改即时生效 {#changes-are-live}

保存模板会立即把修改发送到其上的每个节点。不需要手动同步或重启。

- 每个节点只应用发生变化的部分。添加或编辑一个入站不会影响其他入站及其连接。
- 路由、DNS 和规则集的修改也会就地应用。
- 用户加入或离开模板时，也以同样方式到达其节点。大多数入站在更新用户列表时不会断开任何人。少数类型会重建该入站；WireGuard 客户端会在约二十秒内重新连接。

如果节点拒绝某个配置，它会继续运行之前的配置，节点所在行会显示错误。修正模板后重新保存即可。面板和节点如何就变化内容达成一致，见 [[config-sync]]。

## 预设 {#presets}

**路由**和 **DNS** 标签页各有一个**从预设应用**按钮。

**路由预设**用面板已镜像的列表生成路由配置：

| 预设 | 作用 |
| --- | --- |
| **拦截广告** | 拒绝广告与追踪列表。 |
| **伊朗 + 拦截广告** | 伊朗的域名和地址直接从节点出网，不再继续转发，同时拒绝广告列表。 |
| **中国 + 拦截广告** | 对中国的域名和地址做同样的处理。 |
| **俄罗斯 + 拦截广告** | 对俄罗斯的域名和地址做同样的处理。 |
| **拦截 BT 下载** | 把看起来像 BitTorrent 的流量发往一个由节点计数的拦截出站。添加在现有规则之前。 |

应用路由预设会**替换**模板的规则，因为规则的顺序就是路由本身。**拦截 BT 下载**是例外：它把自己的规则添加在你的规则之前，不改动其他内容。预设所需的规则集会加入模板的选择中。如果面板还没有其中某个规则集，对话框会列出它的名称，并提供**添加列表并应用**，先下载这些列表。

**DNS 预设**用加密解析器替换模板的 DNS 配置：通过 DNS-over-TLS 使用 Cloudflare、Google、Quad9 或 AdGuard，或使用节点的**系统解析器**。AdGuard 在解析器层面拦截广告，因此请用它代替**拦截广告**路由预设，不要两者同时使用。

你可以通过预设目录中的文件添加自己的预设，或修改内置预设。见 [[routing#your-own-presets]]。

## 删除模板 {#deleting-a-template}

删除模板会把它从所有运行它的节点上移除，这些节点在你为其指定另一个模板之前不提供任何服务。属于该模板的用户会失去这一成员关系。如果这些节点需要继续服务，请先把它们换到新模板。模板所选的入站、出站、端点和规则集仍保留在各自的池中。
