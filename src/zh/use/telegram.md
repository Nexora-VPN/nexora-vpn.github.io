# Telegram

Telegram 服务把面板的通知发送到 Telegram 聊天：某位客户即将到期或流量即将用完、某个节点宕机、某次备份失败。每个聊天都配对到一个面板账户，只接收该账户有权查看的内容，因此代理商的聊天只会收到关于它自己客户的通知。已配对的聊天还可以向 Bot 提出几个只读查询。该服务位于 **服务 → Telegram**，由主管理员设置。

## 设置 Bot {#setting-up-the-bot}

1. 在 Telegram 中找到 **@BotFather**，发送 `/newbot`，复制它给你的令牌。
2. 把令牌粘贴到 **Bot 令牌** 中。请为面板使用一个专用 Bot：配对聊天时，面板会读取 Bot 收到的消息，如果另一个程序也在读取同一个 Bot，消息会先被它取走。
3. 如果这台服务器无法访问 `api.telegram.org`（它在一些国家被封锁），请填写以下其中一项：
   - **代理**：`socks5://host:port` 或 `http://host:port`。用户名和密码写在地址中：`socks5://user:pass@host:port`。
   - **Bot API 地址**：你在某处运行的、能访问 Telegram 的 Telegram Bot API 服务器，用来代替代理。
4. 打开 **服务已开启**，保存，然后点击 **测试**。测试使用已保存的设置，因此请先保存。

和所有服务一样，它在关闭时不做任何事。令牌保存后不会再显示：输入框中显示 *已设置——留空则保持不变*，留空即保留已保存的值。**上次运行** 显示该服务最近一次执行操作的时间，如果失败，还会显示最近一次错误。

## 配对聊天 {#pairing-a-chat}

1. 点击 **配对聊天**。
2. 选择聊天接收哪个 **账户** 的通知。
3. 选择通知的 **语言**。
4. 选择 **事件**：**该账户有权查看的全部事件**（包括以后版本新增的事件），或取消勾选后自行选择。账户无权查看的事件显示为灰色，其聊天永远不会收到。
5. 点击 **获取代码**。

随后对话框会显示三种完成方式：

- 一个链接和一个二维码：在应接收通知的 Telegram 账户中打开它，并点击 **Start**；
- 代码本身，用于手动发送给 Bot；
- 对于群组，可以点击 **将 Bot 添加到群组**，选择群组后代码会发送到那里；或者在 Bot 已加入的群组中发送 `/start@yourbot CODE` 这一行。

在群组中，Bot 只接收以名称指明发给它的命令，因此直接在群组中发送代码不会被看到。代码在十分钟内有效。Bot 一收到代码，对话框就会显示 **聊天已配对**。

::: warning
群组中的每个人都能读到其账户有权查看的内容。只有当群组的每个成员都可以查看某代理商的客户时，才把该群组配对给这个代理商。
:::

### 每个账户自行配对 {#each-account-pairs-its-own}

每个账户都可以在自己菜单的 **我的 Telegram** 中，按同样的步骤配对自己的聊天。代理商无需主管理员协助。**我的 Telegram** 还会列出该账户自己的聊天及其投递记录。

## 收到的内容 {#what-arrives}

通知是一条使用聊天所选语言的简短消息：发生了什么，然后是对人有用的字段（账户、其流量和日期、节点及其错误）。[[reference/events]] 中的任何事件都可以选择。运营者通常保留的几个事件：

| 事件 | 时机 |
| --- | --- |
| `user.quota_warning`、`user.expiring` | 账户接近其流量上限或到期日期 |
| `user.disabled` | 账户因流量或日期被停用 |
| `node.disconnected`、`node.connected` | 节点停止或恢复响应 |
| `node.disk_high`、`node.memory_high` | 节点的磁盘或内存超过阈值 |
| `panel.backup_failed`、`panel.backup_upload_failed` | 备份或其上传失败 |
| `admin.login_new_ip` | 某个账户从新地址登录 |

代理商的聊天只会收到关于它自己的用户和它自己账户的事件：节点和面板事件永远不会发给它。

## 聊天列表 {#the-chat-list}

每一行显示聊天、其 **账户**、**事件**、**语言** 和 **配对时间**，并有一个用于暂停的开关。在行菜单中：

- **编辑**：修改事件或语言。
- **发送测试消息**。
- **投递记录**：发送到该聊天的每条通知，包括已送达、等待重试或已放弃的，附有 Telegram 的响应，每条都可以点击 **重新发送**。
- **取消配对**：聊天不再接收通知；重新配对需要新的代码。

聊天的重试方式与 Webhook 相同（参见 [[webhooks]]），因此在 Telegram 或代理不可用期间发送的通知，会在恢复后送达。服务关闭期间，已配对的聊天不会收到任何内容，直到服务重新开启。

## 命令 {#commands}

在已配对的聊天中：

| 命令 | 返回 |
| --- | --- |
| `/status` | 概览：按状态统计的账户数和当前在线数（代理商只看到自己的），以及（对主管理员和操作员）节点情况 |
| `/user name` | 单个账户：流量、到期时间、是否在线（代理商只能查自己的） |
| `/node name` | 单个节点（主管理员和操作员） |

在群组中，请加上 Bot 的名称：`/user@yourbot name`。这些命令只读取数据；聊天中的任何操作都无法修改面板。如果聊天配对的代理商账户已过期，Bot 会告知这一点。

## 移除账户的聊天 {#removing-an-account-s-chats}

删除账户会移除它的聊天。主管理员在 [[admins]] 页面重置其密码时也会移除，这样持有旧密码的人就无法再读取该账户的通知。之后账户可以重新配对自己的聊天。
